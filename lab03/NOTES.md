git diff — показывает различия между версиями (например, между рабочей директорией и коммитом).
git show — выводит детали одного коммита (метаданные и изменения).
git log — отображает историю коммитов.
git log -S <строка> — ищет коммиты, где изменилось число вхождений строки.
git blame <файл> — показывает, какой коммит и кто последний раз менял каждую строку файла.
git restore file — отменяет git add для файла: правки остаются в файле, убираются из индекса.
git restore --source=HEAD file — перезаписывает файл версией из последнего коммита: все правки теряются.
git restore --source=HEAD --staged file — убирает изменения только из индекса, в файле правки сохраняются.
Проще говоря: без --source команда работает с индексом, с --source — берёт конкретную версию из истории и может затереть правки.
Отмена коммитов: revert vs reset
git revert
Суть: Создаёт новый коммит, который инвертирует изменения целевого коммита.
История: Не переписывается. Исходный коммит остаётся в логе.
Безопасность: Высокая. Подходит для отмены опубликованных коммитов в общих ветках.
Команда: git revert <commit-hash>
git reset --hard
Суть: Удаляет коммиты из истории, откатывая ветку к указанному состоянию.
История: Переписывается. Коммиты исчезают.
Безопасность: Низкая. Нельзя использовать на опубликованных ветках, если над ними работает команда.
Команда: git reset --hard <commit-hash>

Почему revert безопаснее для опубликованной истории?
При работе в команде история коммитов — это общий контракт. git reset нарушает этот контракт, меняя уже опубликованные данные, что приводит к рассинхронизации у всех участников. git revert сохраняет целостность истории и просто добавляет логическое исправление сверху, что позволяет коллегам безопасно обновлять свои локальные копии через обычный git pull.
